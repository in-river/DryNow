# v8.1 UI改善・地点変更対応

実装日: 2026-09-17

## 目的

v8の時間別予報と外干し判定v1を維持しながら、Windowsデスクトップとスマートフォンの双方で情報を読み取りやすくし、ユーザーが地名検索から任意地点を選択できるようにする。

## UI改善

- 画面全体を中央寄せし、コンテンツ最大幅を800pxに制限する。狭い画面では利用可能幅まで縮む。
- 大きな地点見出しを廃止し、画面上部に押下可能な小型地点表示を置く。
- 干し始め時刻のDropdownを、1h、2h、3h、6h、9h、12h、18h、24hの `ChoiceChip` と `Wrap` に変更する。
- 天気、状態アイコン、「外干しOK / 注意 / NG / 判定不能」、主理由を一つの主判定カードへまとめる。状態は色だけでなく文字とアイコンでも示す。
- 気温、湿度、風速、降水確率をカード化する。幅480px以上では2列、未満では1列にする。
- 降水量、使用予報時刻、API格子座標、取得時刻は補助情報として小さく表示する。
- 「干し始め時点の予報による判定」という注意書きとOpen-Meteo帰属表示を画面下部へ移す。

## 地点モデル

`WeatherLocation` は次を保持する。

- `name`: 画面とAPIレスポンスモデルに使用する表示名
- `latitude`: 緯度
- `longitude`: 経度
- `administrativeArea`: 都道府県・地域名（任意）
- `country`: 国名（任意）

初期地点と検索失敗時のフォールバックは春日部市 `35.9795, 139.7523`。検索結果の緯度経度が非有限値または範囲外なら候補から除外する。選択地点は現在のアプリセッション中に保持し、アプリ再起動後の永続化はまだ行わない。

## 地名検索方式とAPI

Open-Meteo Geocoding APIを使用する。

```text
GET https://geocoding-api.open-meteo.com/v1/search
  ?name={検索文字列}
  &count=10
  &language=ja
  &format=json
```

`results` の `name`、`latitude`、`longitude`、`admin1`、`country` を取り込む。同名地点を区別できるよう、候補には地名に加えて都道府県・地域と国を表示する。元JSONは正規化結果と別にメモリ保持し、ログへ出力しない。

日本語で自治体接尾辞を省略した場合、Open-Meteoでは「東京」が0件になり、「熊谷」が別地域の小地名を優先することがある。このため「東京市、東京区、東京都…」「熊谷市…」の順に接尾辞を補い、最初に候補が得られた検索結果を採用する。すでに都道府県・市区町村・駅まで入力されている場合と英字入力では補完しない。

## 地点変更フロー

```text
地点表示を押す
  -> 検索文字列を入力
  -> Geocoding APIから候補取得
  -> 候補を選択
  -> WeatherLocationを画面状態へ保存
  -> 新しい緯度経度で時間別予報を取得
  -> 予定時刻の予報を選択
  -> 既存DryingEvaluatorで判定
  -> UIを更新
```

地点選択と同時に新しい予報Futureへ切り替える。取得中は選択した地点名とloading表示だけを出し、以前の地点の予報・判定を残さない。検索ダイアログを閉じた場合は地点と予報を変更しない。

## 状態管理

追加の状態管理ライブラリは導入しない。`WeatherPage` のStateが次を保持する。

- 選択地点 `WeatherLocation`
- 選択した干し開始オフセットと予定時刻
- 選択地点に対応する `Future<ForecastResponse>`

予報のloading / data / errorは `FutureBuilder`、地点検索のloading / candidates / empty / errorは検索ダイアログ内のStateで分離する。判定結果は予報データから都度算出し、重複状態として保持しない。

## エラー処理

- 空検索: API通信せず入力を促す。
- 検索結果0件: 表記を変えて再検索するよう表示する。
- Geocoding通信失敗、HTTPエラー、不正JSON、タイムアウト: 検索ダイアログ内に理由を表示し、ダイアログを閉じず再検索できる。
- 地点変更後の予報取得失敗: 選択地点は維持し、予報エラーカードと再読み込み操作を表示する。
- 古い地点の非同期レスポンス: 最新のFutureだけを `FutureBuilder` の表示対象にする。

## 現在地対応

v8.1では未実装。地名検索を優先し、既存のAndroid / iOS / Windows設定を不用意に変更しないためである。

次の小タスクでは、位置情報プラグインの選定に加えて以下が必要になる。

- Androidの位置情報権限とサービスOFF・権限拒否・永続拒否の処理
- iOSの利用目的文言と権限状態の処理
- Windowsの位置情報機能・権限・対応プラグインの確認
- 座標から表示名を得るreverse geocoding、または座標表示時のUI仕様
- Widgetテストでは位置情報取得を注入可能にする抽象化

## 制約

- 地名検索結果の品質と「駅」などの検索可否はOpen-Meteo Geocoding APIの収録データに依存する。
- 選択地点はアプリ終了後に永続化しない。
- 判定対象は干し始め1時点のみ。干している時間帯全体と乾燥時間は扱わない。
- 判定閾値、予報取得項目、30分以内の最近傍予報選択はv8から変更していない。
- 大規模なデザインシステムや外部状態管理ライブラリは導入していない。

## v9への引き継ぎ

1. 干す時間の長さを選択し、開始から終了までの複数予報を評価する。
2. 途中の雨・強風などをまとめた時間帯判定と理由表示を設計する。
3. 地点と干し時間の設定を端末へ永続化するか決定する。
4. 現在地取得を独立タスクとして実装し、全プラットフォームの権限挙動を実機確認する。
5. 実際の外干し結果を使い、予報と判定閾値を検証する。

予報モデルと時刻選択は[予報ベースの実用化v8](FORECAST_IMPLEMENTATION_V8.md)、判定閾値は[外干し判定v1](DRYING_RULES_V1.md)を参照する。
