# v8 予報ベースの実用化

実装日: 2026-09-17

> v8時点の仕様記録。固定地点とUIはv8.1で更新した。現行仕様は[UI改善・地点変更対応v8.1](UI_LOCATION_V8_1.md)を参照する。

## 目的

ユーザーが指定した干し始め時刻に対応するOpen-Meteoの時間別予報を、既存の外干し判定v1へ入力し、Flutter画面で「OK / 注意 / NG / 判定不能」と理由を確認できるようにする。

構成は `Open-Meteo -> WeatherApi -> ForecastSeries / HourlyForecast -> DryingEvaluator -> Flutter UI` とし、HTTP、API固有JSON、判定、表示の責務を分離する。既存の現在値取得と `evaluate` は互換性のため残す。

## 取得する予報

`WeatherApi.fetchHourlyForecastByCoordinates` がOpen-Meteo Forecast API `/v1/forecast` をGETする。

- `temperature_2m`: 気温（℃）
- `relative_humidity_2m`: 相対湿度（%）
- `wind_speed_10m`: 風速（m/s）
- `precipitation`: 1時間の降水量（mm）
- `precipitation_probability`: 降水確率（%）
- `weather_code`: WMO天気コード
- `time`: 予報対象時刻

取得範囲は3日間。`timeformat=unixtime`、`timezone=GMT` としてUTCの絶対時刻でモデルに保持し、画面表示時だけ端末のローカル時刻へ変換する。APIのraw JSONは正規化値とは別に `ForecastResponse.rawJson` へ保持し、ログへ出力しない。

## 時刻選択

v8のUIは「現在から何時間後に干すか」を選ぶ。選択肢は1、2、3、6、9、12、18、24時間後。

予定時刻に最も近い時間別予報を使用する。許容差は30分以内で、ちょうど同距離なら未来側の予報を選ぶ。30分以内に予報がなければ判定不能とする。比較はUTCへ変換した絶対時刻で行うため、端末のタイムゾーンと日付跨ぎを同じ処理で扱う。

画面を開いた時点と選択変更時に予定時刻を確定する。予報更新時は、選択中の「何時間後」を更新時点から再計算する。

## 外干し判定への接続

`HourlyForecast.dryingConditions` が、気温、湿度、風速、降水量、降水確率、降水有無、予報時刻を既存の `DryingConditions` へ変換する。判定の閾値と優先順位はv1のまま変更していない。

予報は `DryingEvaluator.evaluateForecast` で評価する。未来の予報時刻へ現在値用の「60分より古い」ルールは適用しない。代わりに予報時刻の欠損または過去時刻を判定不能とし、v8で正式接続した降水確率は必須入力とする。

値の `0` と欠損は区別する。null、NaN、infinity、範囲外の湿度・降水確率、負の風速・降水量に加え、-100℃未満または70℃超の気温、150m/s超の風速を不正値として扱う。

## UI

画面には次を表示する。

- 干し始めるまでの時間と予定時刻
- 判定に使用した時間別予報の時刻と天気
- 気温、湿度、風速、降水量、降水確率
- 外干しOK、外干しは注意、外干しNG、判定できません
- 該当した判定理由
- API格子座標、アプリ取得時刻、Open-Meteoの帰属表示

開始時刻の1時間予報だけによる判定であり、干している時間帯全体や乾燥完了を保証しない旨も表示する。

## エラー時の挙動

- タイムアウト、接続失敗、HTTPエラー、不正JSON: エラー内容と再読み込みボタンを表示する。
- 時間別予報なし、対応時刻なし: クラッシュせず「判定できません」と理由を表示する。
- 必須値の欠損・単位不一致・不正値: 0に置換せず判定不能理由を表示する。
- 雨・雪・雷雨、強風など独立に確認できたNG条件は、他項目の欠損で隠さない。
- 表示中に予報時刻を過ぎた場合は毎分再評価し、過去の予報によるOK表示を取り下げる。

## 現時点の制約

- 地点は既存検証地点の春日部駅周辺 `35.9795, 139.7523` に固定している。
- 判定対象は干し始める1時点の予報で、干している期間全体の悪化を評価しない。
- 乾燥時間、完了予定時刻、衣類量・素材、日射、突風は扱わない。
- 予報精度とv1閾値は実際の外干し結果で未検証。
- 予報の発表時刻はAPIレスポンスにないため、通信時刻を別に保持する。アプリを開いている間の自動再取得は行わない。

## 次フェーズ候補

1. 干す時間の長さを入力し、開始から終了まで複数の時間別予報を評価する。
2. 現在地・地点選択と端末権限を設計する。
3. 実際の乾燥結果を収集し、v1閾値と予報精度を検証する。
4. 日射、雲量、露点、突風を追加し、乾燥時間推定へ進む。
5. バックグラウンド更新と、天候悪化時の通知を検討する。

判定閾値は[外干し判定v1](DRYING_RULES_V1.md)、API採用理由は[API比較結果](API_COMPARISON_RESULT.md)を参照する。
